Azure Local: dari deployment sampai VM pertama

Panduan berbasis kejadian nyata. Fokusnya pada satu pertanyaan yang paling sering menyesatkan: kenapa tombol Create VM tetap kosong padahal host sudah Windows Server 24H2 dan status Arc sudah Connected.

Azure Local 23H2 / 24H2 Azure CLI Arc Resource Bridge Terverifikasi 21 Agustus 2026

Peta kesiapan: tiga lapisan yang sering dikira satu

Kegagalan paling umum terjadi karena lapisan 1 dianggap membuktikan lapisan 3. Padahal tidak.

Lapisan 1 — Host
OS 24H2, node Connected
Membuktikan mesin terdaftar ke Arc. Tidak membuktikan apa pun soal kemampuan membuat VM.
Lapisan 2 — Control plane
Resource Bridge + Custom Location
Ini gerbang sebenarnya. Selama belum ada, portal menampilkan empty state yang membingungkan.
Lapisan 3 — Resource VM
Logical network, storage path, VM image
Tanpa image, tombol Create VM ada tapi tidak ada yang bisa dipilih.

Aturan praktis: kalau portal bilang "No Azure Local VMs to display", jangan periksa versi OS lebih dulu. Periksa lapisan 2.

1. Prasyarat Azure

Dikerjakan sekali per subscription. Melewatkan satu provider akan muncul sebagai error yang tidak jelas jauh di kemudian hari.

Daftarkan resource provider berikut. Microsoft.EdgeMarketplace paling sering terlewat karena baru dibutuhkan saat membuat VM image, bukan saat deployment.

PowerShell
az provider register --namespace Microsoft.AzureStackHCI
az provider register --namespace Microsoft.HybridCompute
az provider register --namespace Microsoft.HybridConnectivity
az provider register --namespace Microsoft.ExtendedLocation
az provider register --namespace Microsoft.ResourceConnector
az provider register --namespace Microsoft.KubernetesConfiguration
az provider register --namespace Microsoft.EdgeMarketplace

Verifikasi semuanya sudah Registered sebelum lanjut:

PowerShell
$providers = 'Microsoft.AzureStackHCI','Microsoft.HybridCompute',
             'Microsoft.ExtendedLocation','Microsoft.ResourceConnector',
             'Microsoft.EdgeMarketplace'

$rows = foreach ($p in $providers) {
    $state = az provider show -n $p --query registrationState -o tsv
    [pscustomobject]@{ Provider = $p; State = $state }
}
$rows | Format-Table -AutoSize
Kenapa ini penting Tanpa Microsoft.EdgeMarketplace, pembuatan VM image gagal dengan SubscriptionNotRegistered — pesan yang muncul berjam-jam setelah deployment selesai, sehingga mudah dikira masalah cluster.

Peran RBAC

  • Azure Connected Machine Onboarding dan Azure Connected Machine Resource Administrator pada resource group tempat node didaftarkan.
  • Azure Connected Machine Resource Manager untuk resource provider app Microsoft.AzureStackHCI pada resource group tempat image diunduh.

2. Memantau deployment

Deployment Azure Local berjalan sekitar 54 tahap. Yang perlu dipahami: statusnya bertingkat, dan ARM tidak menceritakan semuanya.

Status di level resource group hanya bilang Running. Detail sebenarnya ada di resource deploymentSettings:

PowerShell
$sub = "<SUBSCRIPTION_ID>"
$rg  = "<RESOURCE_GROUP>"
$cluster = "<CLUSTER_NAME>"

$id = "/subscriptions/$sub/resourceGroups/$rg/providers/" +
      "Microsoft.AzureStackHCI/clusters/$cluster/deploymentSettings/default"

az resource show --ids $id --api-version 2024-04-01 -o json

Di dalam responsnya ada daftar tahap lengkap dengan status, startTimeUtc, dan endTimeUtc. Contoh potongan saat deployment masih berjalan:

Jangan panik melihat "Unknown" Unknown berarti tahap belum dimulai. Yang menandakan masalah adalah Failed. Deployment dua node normalnya memakan waktu sekitar 2,5 jam.

3. Diagnosa "No Azure Local VMs to display"

Portal menampilkan dua pesan berbeda untuk kondisi ini, dan salah satunya menyesatkan.

Pohon keputusan

PeriksaPerintahKesimpulan bila tidak sesuai
Deployment selesai? deploymentSettings/default Masih ada tahap InProgress — tunggu, jangan intervensi.
Resource Bridge ada dan Running? Microsoft.ResourceConnector/appliances WaitingForHeartbeat berarti appliance belum lapor ke Azure.
Custom location ada? Microsoft.ExtendedLocation/customLocations Belum ada berarti control plane VM belum terbentuk.
Logical network ada? Microsoft.AzureStackHCI/logicalNetworks Hanya ada InfraLNET berarti belum ada jaringan untuk VM workload.
VM image ada? az stack-hci-vm image list Kosong berarti Create VM tidak punya pilihan image.
Yang tidak membuktikan apa pun Node berstatus Connected dengan OS 24H2. Itu hanya berarti Arc agent berjalan. Kemampuan membuat VM ditentukan oleh Resource Bridge dan custom location, bukan oleh versi OS.

4. Verifikasi control plane

Satu blok perintah untuk memastikan seluruh lapisan 2 dan 3 benar-benar ada.

PowerShell
$sub = "<SUBSCRIPTION_ID>"
$rg  = "<RESOURCE_GROUP>"

$all = az resource list --subscription $sub -g $rg -o json | ConvertFrom-Json

$want = 'Microsoft.ResourceConnector/appliances',
        'Microsoft.ExtendedLocation/customLocations',
        'Microsoft.AzureStackHCI/logicalNetworks',
        'Microsoft.AzureStackHCI/storageContainers',
        'Microsoft.AzureStackHCI/galleryImages',
        'Microsoft.AzureStackHCI/marketplaceGalleryImages'

$all |
  Where-Object { $want -contains $_.type } |
  Select-Object name, type |
  Sort-Object type |
  Format-Table -AutoSize

Kondisi sehat terlihat seperti ini:

ResourceTipeStatus yang diharapkan
<cluster>-arcbridgeappliancesRunning
<custom-location>customLocationsSucceeded
<cluster>-InfraLNETlogicalNetworksSucceeded
UserStorage1 / UserStorage2storageContainersSucceeded
Membedakan Succeeded dari Running Pada Arc Resource Bridge, provisioningState bisa Succeeded sementara status masih WaitingForHeartbeat. Yang menentukan kesiapan adalah status.
PowerShell
az resource show `
  --ids "/subscriptions/$sub/resourceGroups/$rg/providers/Microsoft.ResourceConnector/appliances/<CLUSTER>-arcbridge" `
  --api-version 2022-10-27 `
  --query "properties.status" -o tsv

5. Logical network

InfraLNET yang dibuat otomatis bukan untuk VM workload.

Setelah deployment, biasanya hanya ada satu logical network berakhiran -InfraLNET. Jaringan itu dipakai Arc Resource Bridge dan hanya menyediakan segelintir alamat IP. VM workload memerlukan logical network tersendiri.

PowerShell
$cl = "/subscriptions/$sub/resourceGroups/$rg/providers/" +
      "Microsoft.ExtendedLocation/customLocations/<CUSTOM_LOCATION>"

az stack-hci-vm network lnet create `
  --subscription $sub `
  --resource-group $rg `
  --custom-location $cl `
  --location <REGION> `
  --name <LNET_NAME> `
  --vm-switch-name '"ConvergedSwitch(compute_management)"' `
  --ip-allocation-method static `
  --address-prefixes 192.168.200.0/24 `
  --gateway 192.168.200.1 `
  --dns-servers <DNS_IP> `
  --vlan 200
Perhatikan tanda kutip pada nama switch ConvergedSwitch(compute_management) mengandung tanda kurung. Di Windows, az adalah pembungkus batch, sehingga tanda kurung tanpa kutip akan dipecah oleh cmd. Bungkus dengan '"..."' seperti contoh di atas.

6. VM image Windows

Windows bisa ditarik langsung dari Azure Marketplace lewat URN.

PowerShell
$sp = "/subscriptions/$sub/resourceGroups/$rg/providers/" +
      "Microsoft.AzureStackHCI/storageContainers/<STORAGE_PATH>"

az stack-hci-vm image create `
  --subscription $sub `
  --resource-group $rg `
  --custom-location $cl `
  --location <REGION> `
  --name ws2022 `
  --os-type Windows `
  --publisher microsoftwindowsserver `
  --offer windowsserver `
  --sku 2022-datacenter-azure-edition `
  --storage-path-id $sp

Pantau progres unduhan, karena perintah di atas hanya mengembalikan Accepted di awal:

PowerShell
$id = "/subscriptions/$sub/resourceGroups/$rg/providers/" +
      "Microsoft.AzureStackHCI/marketplaceGalleryImages/ws2022"

$d = az resource show --ids $id --api-version 2025-04-01-preview -o json | ConvertFrom-Json

[pscustomobject]@{
  State   = $d.properties.provisioningState
  Percent = $d.properties.status.progressPercentage
  Version = $d.properties.version.name
  Error   = $d.properties.status.errorCode
} | Format-List

Kalau gagal dengan GenerateTokenFromEdgeMarketplaceServiceFailed

Error ini punya dua penyebab yang sangat berbeda. Bedakan dari isi pesannya:

Isi pesanArtiTindakan
SubscriptionNotRegistered Provider Microsoft.EdgeMarketplace belum terdaftar. Daftarkan provider, lalu ulangi.
NotFound / ResourceNotFound Provider sudah benar, tetapi image itu tidak bisa diterbitkan SAS-nya. Coba SKU lain. Ini bukan masalah izin.
Hasil pengujian tiga URN pada satu sistem yang sama

Pengujian berikut dilakukan berurutan pada cluster yang identik, untuk memisahkan masalah konfigurasi dari masalah ketersediaan katalog.

URNVersi ter-resolveHasil
microsoftwindowsserver:windowsserver:2022-datacenter-azure-editionterisiBerhasil unduh
microsoftwindowsserver:windowsserver:2025-datacenter-azure-edition-smalldiskterisiSAS gagal
canonical:ubuntu-24_04-lts:serverterisiSAS gagal

Versi ter-resolve untuk ketiganya, artinya katalog bisa membaca metadata image. Yang gagal hanya penerbitan SAS untuk sebagian image. Karena itu, kegagalan semacam ini adalah soal ketersediaan image, bukan salah konfigurasi.

7. VM image Linux

Linux tidak bisa ditarik lewat URN. Prosedurnya berbeda sepenuhnya.

Ini bukan bug Daftar image Marketplace yang didukung Azure Local hanya berisi Windows. Untuk Ubuntu dan RHEL, Microsoft mendokumentasikan jalur ekspor VHD.

Alurnya

  1. Buat VM Linux biasa di Azure sebagai sumber.
  2. Bersihkan identitas VM dan ubah datasource cloud-init.
  3. Hentikan VM, ekspor OS disk menjadi SAS URL.
  4. Buat image Azure Local dari SAS URL itu.
  5. Hapus VM sumber.

Langkah 2 — persiapan di dalam VM

Bagian paling krusial adalah mengubah datasource dari Azure ke NoCloud. Tanpa itu, VM tidak akan menerima kredensial saat dibuat di Azure Local.

Bash
set -eu

cloud-init clean
rm -rf /var/lib/cloud/ || true
rm -rf /tmp/* || true
rm -rf /var/log/* || true

rm -f /etc/ssh/ssh_host*

echo 'datasource_list: [ NoCloud ]' > /etc/cloud/cloud.cfg.d/90_dpkg.cfg
cat /etc/cloud/cloud.cfg.d/90_dpkg.cfg

Script itu bisa dijalankan tanpa SSH sama sekali, lewat Run Command:

PowerShell
az vm run-command invoke `
  -g <PREP_RG> -n <PREP_VM> `
  --command-id RunShellScript `
  --scripts "@prep-ubuntu.sh" `
  --query "value[0].message" -o tsv
Dua jebakan di sini Script yang dibuat di Windows berakhiran CRLF dan akan gagal di Linux dengan error $'\r'; konversi ke LF dulu. Selain itu, script multi-baris yang ditempel langsung ke --scripts akan diratakan jadi satu baris dan diam-diam tidak berfungsi — selalu pakai "@file".

Langkah 3 dan 4 — ekspor disk lalu buat image

PowerShell
az vm deallocate -g <PREP_RG> -n <PREP_VM>

$diskId = az vm show -g <PREP_RG> -n <PREP_VM> `
  --query storageProfile.osDisk.managedDisk.id -o tsv

$sas = (az disk grant-access --ids $diskId `
  --duration-in-seconds 86400 --access-level Read `
  --query accessSAS -o tsv | Out-String).Trim()

az stack-hci-vm image create `
  --subscription $sub --resource-group $rg `
  --custom-location $cl --location <REGION> `
  --name ubuntu2404 --os-type Linux `
  --image-path ('"' + $sas + '"') `
  --storage-path-id $sp
Nama propertinya accessSAS, bukan accessSas Kalau salah kapitalisasi, perintah tidak error — ia hanya mengembalikan string kosong, lalu image create mengeluh spesifikasi image tidak lengkap. Gejalanya jauh dari penyebabnya.
Bersihkan setelah selesai Cabut akses disk dengan az disk revoke-access dan hapus resource group sementara setelah image berstatus tersedia.

8. Membuat VM

Setelah image, logical network, dan storage path lengkap.

PowerShell
az stack-hci-vm network nic create `
  --subscription $sub --resource-group $rg `
  --custom-location $cl --location <REGION> `
  --name <NIC_NAME> `
  --subnet-id <LNET_NAME>

az stack-hci-vm create `
  --subscription $sub --resource-group $rg `
  --custom-location $cl --location <REGION> `
  --name <VM_NAME> `
  --image <IMAGE_NAME> `
  --admin-username <USERNAME> `
  --admin-password $env:VM_ADMIN_PASSWORD `
  --nics <NIC_NAME> `
  --hardware-profile memory-mb=8192 processors=4 `
  --storage-path-id $sp
Jangan menaruh password di file atau riwayat perintah Ambil dari variabel lingkungan yang diisi lewat Read-Host -AsSecureString, dan hapus variabelnya setelah selesai. Password VM harus 12–123 karakter serta memenuhi minimal tiga dari empat kategori: huruf besar, huruf kecil, angka, dan karakter khusus.

9. Update Arc agent

Di Azure Local, aturannya berbeda dengan Arc-enabled server biasa.

Jangan update agent secara manual di node Azure Local Dokumentasi Azure Local menyatakan Azure Connected Machine agent dan Arc Resource Bridge diperbarui otomatis ke versi tervalidasi ketika sistem di-update, dan update di luar jalur resmi tidak didukung karena berisiko bentrok dengan Application Control (WDAC).

Jadi banner Advisor "A newer Arc agent version is available" pada node Azure Local tidak diselesaikan dengan menjalankan installer MSI. Jalurnya adalah solution update.

PowerShell
$base = "https://management.azure.com/subscriptions/$sub/resourceGroups/$rg" +
        "/providers/Microsoft.AzureStackHCI/clusters/<CLUSTER>"

az rest --method get --url "$base/updateSummaries/default?api-version=2024-04-01" `
  --query "properties.{Version:currentVersion,State:state,Health:healthState}" -o json

az rest --method get --url "$base/updates?api-version=2024-04-01" `
  --query "value[].{Name:name,Version:properties.version,State:properties.state}" -o table
KonteksCara update agent
Server Arc biasaMSI, Microsoft Update, atau azcmagent upgrade (butuh agent 1.62+)
Node Azure LocalHanya melalui solution update dari halaman Azure Local atau Azure Update Manager
Catatan tentang azcmagent upgrade Perintah ini hanya tersedia mulai agent versi 1.62. Pada versi lebih lama, perintahnya tidak ada — sehingga pada node Azure Local yang tertinggal, satu-satunya jalur benar tetap solution update.

10. Jebakan CLI di Windows

Kesalahan berikut memakan waktu paling banyak justru karena tidak terlihat seperti error.

GejalaPenyebabSolusi
xyz was unexpected at this time JMESPath memakai tanda kurung, misalnya contains(type,'Image'). PowerShell hanya mengutip argumen yang mengandung spasi, sehingga cmd memecah tanda kurung. Filter di sisi PowerShell dengan Where-Object, atau hindari tanda kurung di --query.
An empty pipe element is not allowed foreach dipipe langsung ke Format-Table. Tampung dulu: $rows = foreach (...) { ... } lalu pipe $rows.
$'\r': command not found Script shell dibuat di Windows sehingga berakhiran CRLF. Konversi ke LF sebelum dikirim ke mesin Linux.
Perintah sukses tetapi tidak melakukan apa pun Script multi-baris ditempel langsung ke --scripts lalu diratakan jadi satu baris. Selalu gunakan --scripts "@file".
Unsupported Media Type az rest --method put tanpa header tipe konten. Tambahkan --headers Content-Type=application/json.
Body JSON ditolak walau valid JSON inline kehilangan tanda kutip saat melewati pembungkus batch. Simpan ke file lalu kirim dengan --body "@file.json".
